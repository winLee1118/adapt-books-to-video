# 按条视频生成制作看板（仅显式请求）

## 1. 触发与边界

默认不生成看板，不创建看板映射、HTML 或目录。只有用户明确要求“生成看板”“生成本条视频页面”“更新看板”等才执行本流程。普通初始化、剧本开发、资产生成、QA、导出和最终交付不自动触发。用户本次要求增加技能能力，仅授权代码实现与测试，不表示需要为旧制作项目生成看板。

看板是本地可离线打开的 HTML 页面，无 CDN、外部脚本或服务依赖。生成页面不意味着发布网站；上传或公开发布另按用户要求执行。看板只展示来源记录，不修改 `active-release.json`、制作文档、批准状态或媒体文件，不调用图片、视频或音乐模型。

生成范围服从用户请求：只要求某条视频时只把该条加入本轮 `videos`；明确要求整个项目时才生成全部条视频页面。完整文件索引仍保留，方便查找上游与共用文档。

## 2. 核心单位与显眼标题

一条视频一个看板页面，入口 `index.html` 汇总视频页面。页面主标题必须是“第 N 场 · 第 M 条视频”或“第 N 集 · 第 M 条视频”；项目同时有集数与场次时显示“第 N 集 · 第 S 场 · 第 M 条视频”。分条剧本区域属于这个明确的视频单元。

`VIDEO-UNIT` 是用户制作中的一条视频，不强制等同于一个电影镜头、一次生成任务或最终影片。一条视频可以关联多个 `GEN` 或 `SHOT`；保持 `job_ids` 显式映射，不从文件名、排序、修改时间或最高版本号猜测编号。`video_number` 在对应场／集范围内计数。编号或归属无法从生效剧本、导演台本、制作清单确定时，先核对真实记录；必要时询问用户，不伪造场次。

## 3. 文件归属与覆盖

先读取 `active-release.json`、当前剧本分条/细化稿、导演台本及实际文件树，建立映射：

- **本条文件**：属于当前条视频的剧本分条、细化、导演台本/调度、角色/场景/道具、锚点、分镜、提示词、生成结果、声音、QA 和修复记录。允许一个共用源文件通过精确行号映射到多条视频。
- **项目共用**：需求、考证、风格、角色/场景设定、模型能力、来源、总剪辑等共用文档，明确标注共用。
- **完整文件索引**：涵盖工作流实际形成的文件，包括当前、历史、共用和未归属文件。未归属文件不擅自分配到某条视频；历史文件不自动当作当前生效版本。

排除密钥/私密配置、`.git`、缓存和看板输出自身。源文件链接采用相对于 HTML 的项目内路径，保留实际目录结构。移动看板时应连同制作项目移动，否则媒体与源文件链接会失效；看板不是把全部素材嵌入单个 HTML 的交付格式。

## 4. 按需映射文件

只有看板被请求时才在项目根目录创建 `dashboard-map.json`。下例是通用字段示意，路径和编号必须替换为实际登记内容，不是现成作品案例：

```json
{
  "schema_version": 1,
  "project_title": "项目名称",
  "shared_files": [
    {"path": "00-brief.md", "label": "需求简报"},
    {"path": "04-style-bible.md", "label": "风格合同"}
  ],
  "videos": [
    {
      "id": "VIDEO-UNIT-01",
      "episode_number": 1,
      "scene_number": 2,
      "video_number": 1,
      "title": "本条叙事任务",
      "job_ids": [],
      "asset_ids": [],
      "files": [
        {"path": "14-screenplay.md", "group": "script_breakdown", "label": "本条剧本分条", "line_start": 10, "line_end": 18},
        {"path": "14-screenplay.md", "group": "script_detail", "label": "本条动作与对白细化", "line_start": 20, "line_end": 35},
        {"path": "20-director-design.md", "group": "director", "label": "本条导演台本", "line_start": 12, "line_end": 24},
        {"path": "08-video-prompts.md", "group": "prompts", "label": "本条提交提示词", "line_start": 8, "line_end": 22}
      ]
    }
  ]
}
```

- `id` 必填、唯一且稳定；场/集/视频的组合也必须唯一。
- `video_number` 必填；`scene_number` 和 `episode_number` 至少填一个，所有编号为正整数。
- `files` 项必须给项目内相对路径；`group` 可为 `script_breakdown / script_detail / director / assets / storyboards / prompts / sound / qa / other`，默认 `other`。
- `line_start` 和 `line_end` 同时填写，包含起止行，必须在真实文件范围内；两者都不填时展示整份源文件，并提示整稿不等于本条内容。
- `label` 是页面显示名称；`status` 仅采用实际登记状态，缺失时显示未登记。禁止为了看板好看而填 PASS。
- `job_ids` 来自当前清单。渲染器按实际 `prompt_path / capability_record / review_path / input_ids / result_asset_id` 附加文件与资产状态；未知 ID 报错，不自动换用旧任务。
- `asset_ids` 可显式关联本条的资产。尚未有文件的提示词/素材以待登记、缺失或待生成表示，不捏造预览。
- `shared_files` 是显式共用映射，使用同样的路径、标签与可选行范围。完整文件索引由实际文件树补全，保证未映射文件仍可找到。

同一项目中多个阶段写在不同版本文件时，映射到生效稿并显示实际状态。仍需提供历史文件入口。源文档行号变化后，先重新核对摘录，再刷新页面；不能沿用已偏移的行号。

## 5. 生成与刷新

从技能目录运行（`--project` 指向制作项目，其他路径相对于该项目）：

```bash
python scripts/generate_dashboard.py --project /path/to/project --generate
```

输出：`reports/boards/index.html`、每条视频一个 HTML，以及 `dashboard-generated.json` 快照记录。后者记录生成时间、映射哈希、生效版本、页数和索引文件数，不进入媒体输入或批准清单。

只在用户明确要求更新已有看板时运行：

```bash
python scripts/generate_dashboard.py --project /path/to/project --generate --refresh
```

`--manifest` 可指定其他映射文件，`--output` 可指定项目内专用输出目录。默认拒绝覆盖已有目录；`--refresh` 只允许刷新有生成记录的看板目录，保留无关文件和不再使用的旧页面，但当前索引只链接本轮页面。源文稿或资产更新不会自动更新页面，须说明这是快照。

## 6. 页面与验收

页面包括显眼的场/集/条编号、稳定视频单元 ID、生效版本、快照时间、关联生成任务及其真实状态；分区展示剧本分条、剧本细化、导演台本、资产、分镜锚点、提示词、声音剪辑、验收修复和其他文件。文本可阅读/复制，图片、视频、音频可预览，其余格式可打开源文件；长文预览截断时明确提示并保留原文链接。HTML/脚本源码只作为转义文本或链接，不执行源文档内的指令。

生成后核对：

1. 每页编号与剧本分条、导演台本、制作记录一致；一页只代表一个视频单元。
2. 抽查分条、细化、导演段落和提示词摘录，确认未混入其他条内容。
3. 本条／共用／未归属区分正确；完整索引覆盖实际工作流文件，排除私密配置与自身输出。
4. 抽查源文件、图片、视频、音频链接；缺失文件如实展示，没有伪造素材或批准状态。
5. 实际打开索引与至少一条视频页面，检查桌面/窄屏可读性、检索与复制操作。没有浏览预览工具时记录“页面运行未验证”，不要宣称已完成视觉验收。

交付本地入口与相关视频页面路径，说明当前包含的场/集/条、未归属/缺失项、快照性质和实际验证结果。未请求看板时，保持普通交付，不主动补生成。
