# 角色与场景参考资产策略

## 适用范围

在生成角色参考、场景参考、局部特写、色卡或为视频模型选择输入图时阅读本文件。

## 证据边界

以下规则用于组织静态角色与场景资产；它们是制作方法，不构成视频模型能力或生成成功的保证：

- 多格、文字与细节过密的资产卡会压缩单个脸部、表情和材质区域的有效像素，因此交付卡必须限制格数、限制文字并保证单格脸部足够大；
- 角色身份、三视图与剧情表情要在版面上分区呈现，使每个区域都能被放大检查；
- 同一场景的多个机位要先服从文字空间锁、再围绕稳定主地标组织，才能跨镜头验证空间一致性；
- 色卡应作为独立风格约束，与场景卡和中文提示词分别管理。

本工作流在此基础上确定：交付物是成品整版卡，不是一批独立过程图。拆分只发生在版面分区上，不发生在文件数量上。


## 交付优先原则

本工作流只交付成品卡，不交付过程图。

1. 角色与场景的正式交付物是下面定义的三种卡：`CHAR-xx-PROFILE-CARD`、`CHAR-xx-EXPRESSION-CARD`、`SCENE-xx-MULTIANGLE-CARD`。每张卡直接按整版版式一次生成，不再先铺一套独立脸部图、三视图、表情图、方向图再拼版。
2. 不生成、不交付、不入清单的过程图包括：单独的 `FACE`、`FRONT`、`SIDE`、`BACK`、单张 `EXP`、服装拆解图、道具拆解图、低密度双区卡、标注 `MAP` 坐标图、区域引导图、单张 `ANGLE` 方向图。`SCENE-xx-SPATIAL-LOCK` 是文本状态；每个 recurring scene 都必须生成无字的内部顶视 `SCENE-xx-GEOMETRY-PLAN`，经拓扑验收后才可出场景卡；它不交付、不直接送入视频模型。
3. 交付卡同时是人工审核件和视频模型参考件。逐项区分 `QA_ONLY` 与可上传参考：仅经当前任务审核且职责明确的交付卡或裁切可作模型输入；白描按结构参考模式执行，不需要复制一套无区别源图。
4. 只有当整版卡的某一格未通过验收时，才重出那一格并合回原版式；其余已通过的格保持像素不变。重出的单格属于修复中间件，存入 `reports/retries`，不进入交付目录。
5. 每个角色只保留一张资料卡和一张表情卡，每个场景只保留一张多机位卡。同一资产升版保留旧文件追溯；active-release.json 明确当前生效版本和 SUPERSEDED 状态，不覆盖已提交任务的文件或哈希。

## 角色交付卡

### `CHAR-xx-PROFILE-CARD`：角色资料卡与三视图合版

一张 16:9 整版，左右分区，一次生成：

1. **左区（约 36%–42% 宽）**：标题「角色资料卡」置于左上，字号克制。下方一张大尺寸身份肖像，取头肩景别，脸部占该区高度的一半以上，必须能放大检查眉毛、眼睑、视线、嘴唇、下颌、皮肤纹理与发际。
2. **右区（约 58%–64% 宽）**：标题「三视图」置于该区左上。下方并排三张等高全身图，依次为正面、严格 90 度侧面、背面。三格人物身高一致、脚部完整不裁切、服装层次与配饰连续。
3. **统一背景**：全版使用同一米白或暖灰资料页底色，人物背景为无杂物的柔和渐层影棚灰。左右两区共用一套光位，默认左上主光。
4. **文字上限**：全版只允许出现「角色资料卡」「三视图」两处标题，以及必要时每个视角下方的一个短中文标签。禁止长文案、色板、服装结构拆解、道具拆解、小姿势矩阵、数据标注、装饰图标、软件界面、字幕与水印。
5. **同一性要求**：四个视图（肖像＋三视图）必须是同一人：同一脸型、年龄、发型、服装层次、缝线、配饰与鞋履。左区肖像的五官即身份基准，右区三视图不得出现另一张脸。
6. **光线边界**：本卡的均匀资料光只用于检查身份与服装，绝不作为剧情镜头的肖像光。剧情镜头必须以 `SHOT-xx-ANCHOR` 和场景卡的主光、环境补光、边缘色温和景深重新整合人物。

### `CHAR-xx-EXPRESSION-CARD`：表情参考卡

一张 16:9 整版，一次生成：

1. **页眉**：居中或偏左排「表情参考」中文主标题，其后加一条细竖线与英文副标题 `EXPRESSION REFERENCE`，英文字距放宽。页眉只此一行。
2. **网格**：默认 3 列 × 2 行共六格。每格为独立圆角矩形，细边框，格内为头肩特写，脸部占格高一半以上，可放大检查七区表情。仅当交付分辨率不足以保证单格脸部可检查时才降为 2×2 四格。
3. **标签**：每格正下方两行居中标注，上行为短中文表情名，下行为对应英文全大写名，如「平静 / CALM」「微笑 / SMILE」「认真 / SERIOUS」。表情名取自剧情实际需要的表情，不凑数。
4. **底色与留白**：与资料卡同一米白页底，格间留均匀窄间距，不铺装饰纹样。
5. **禁止项**：不混入全身图、色板、服装图、道具图、长说明、箭头、框选、光标、界面残留与字幕。
6. **同一性要求**：六格必须与资料卡左区肖像是同一人，同一发型、同一服装领口、同一光位；只允许表情、视线与头部朝向变化。
7. **场景边界**：表情卡不控制剧情场景的光线、皮肤高光或背景景深；它只提供指定表情的可见方向。

## 场景交付卡

### `SCENE-xx-MULTIANGLE-CARD`：固定空间九机位卡

先在 `06-scene-bible.md` 完成 `SCENE-xx-PRODUCTION-DESIGN-BREAKDOWN` 和 `SCENE-xx-SPATIAL-LOCK`：前者锁定故事任务/证据问题、人物目标与阻力、英雄/行动道具、布景簇、动线、实景光和终态；后者锁定坐标/参考边、空间边界、开口、主地标、固定物件位置和朝向、演员区、光向、V01–V09 与可见性矩阵。二者都是文本状态，不额外计入图片。随后必须生成一个内部、无字的顶视 `SCENE-xx-GEOMETRY-PLAN` 检查平面拓扑与道具位置；该图不交付、不直接送入视频模型，未通过时不得生成场景卡。

唯一的场景交付图是一张 16:9 整版，一次生成：

1. **版式**：3×3 九格铺满整幅画布，九格等大，仅用 2–6 像素细分隔线，不留页边、不设标题栏。
2. **零文字**：全版不出现任何标题、机位名、时间码、字幕、光标、红框、箭头或软件界面。
3. **九格分工**：V01 入口/主地标，V02 左侧关系全景，V03/V04 行动面 A/反打，V05/V06 行动面 B/反打，V07 远端关系全景，V08 门洞/阈值，V09 安全插入或对侧视角。机位名只写在文档，不能写进卡片。
4. **空间一致性**：主地标在至少六格可见；每格还保留可见性矩阵声明的至少两项固定关系。固定物件可以被遮挡，但不得移动、复制、镜像、无因旋转或改变材质。
5. **光线与时间**：九格共用同一时间、天气、季节与主光方向，材质与色调一致。
6. **同一空间要求**：九格必须是同一处地点，不得出现风格相似但布局不同的另一处场地。门窗、通路、座位、器具与视线方向必须符合空间锁的使用关系，不能为了面对镜头而转向；V03–V06 必须可读出人物接近/避让/使用英雄道具或被阈值阻挡的关系，除非拆解表已给出合理的无道具留空。
7. **受限回退**：只有交付分辨率或经核实的目标界面无法让九格地标可检时，才可改为 `SCENE-COMPACT-2x2`；在场景 bible 中写能力原因、所保留的 Vnn、未生成机位和风险。

## 故事板最终交付

1. 每个连续片段直接生成一张 `SHOT-xx-CONTACT`：默认 3×2 紧凑宫格、细分隔线、无大标题带；允许在安全区放小型中文时间码，但不得遮挡脸、手、道具或固定地标。
2. 六格必须来自同一锁定布景和一条连续摄影机语言；它们呈现同一 `ACTION-PROP-BEAT` 的准备、压力、可见变化、余波与终态。允许有动机的推进/跟移/焦点转移或全身调度；至少三格须显示人物—物件或人物—空间的可检查状态改变。不得出现六个各自想象的房间，也不得以六个近似站姿冒充影视分镜。
3. 单格未通过时只重出该格并合回原版，重出件存入 `reports/retries`，不单独交付。
4. 视频模型优先引用 `SHOT-xx-ANCHOR`；联系表默认只作 QA，只有目标明确支持且选择故事板输入模式才上传；`SHOT-xx-ANCHOR` 是唯一保留的单幅交付图，因为它就是成片首帧。

## 色卡与风格参考

1. 只使用有权使用且可归属的影视/摄影风格参考。
2. 提取五至八个大色块，并在中文文本中记录主色、辅色、强调色、对比度、饱和度、色温、高光、阴影、颗粒和材质响应。
3. 保存清洁无字色卡供生成使用，另存带中文说明的审核版。
4. 色卡只控制色彩与材质观感，不控制人物身份、场景几何或动作。

## 每镜头最小充分引用

从批准交付卡及其经 QA 的内部干净裁切中选，按优先级排列，不为凑数量叠加素材：

1. `SHOT-xx-ANCHOR`：首帧、构图、人物位置、摄影机和光线。
2. `CHAR-xx-PROFILE-CARD`：控制身份、身体比例、服装层次与配饰。
3. `CHAR-xx-EXPRESSION-CARD`：只在镜头需要指定表情时加入。
4. `SCENE-xx-MULTIANGLE-CARD`：只控制空间几何；注明引用 Vnn 和三项可核验关系。若锚点已经充分，不重复加入。
5. `STYLE-COLOR-xx`：只控制色调、对比和材质响应。

若目标模型只接受单张参考，按上表顺序取第一项；若整卡的文字/多视图干扰或输入要求需要干净单人区域，从 `CHAR-xx-PROFILE-CARD` 左区肖像做无损裁切临时使用，裁切件不入交付目录。

若目标模型的参考数量、权重或输入类型未由官方资料确认，不写具体上限或权重；改写为按界面实测后选择最小充分集合。

对近景人物，先检查 `SHOT-xx-ANCHOR` 的 `FACE_INTEGRATION_LOCK`：资料卡只锁脸与服装，场景卡锁光向与环境，锚点才负责脸部阴影层次、皮肤/头发/服装材质分离、人物边缘色温与景深。不要让人物资料卡取代场景光。

## 验收

- 放大检查脸、眼睛、嘴、手、服装接缝和道具，确认关键区域在整版卡内仍不是小缩略图。
- 检查资料卡的肖像与三视图、表情卡六格之间是同一人：脸型、年龄、发型、服装层次、配饰、鞋履与光位一致。
- 检查九格回到同一 `SCENE-xx-SPATIAL-LOCK`：主地标至少六格可见，光向、时间、材质无漂移，固定物件未移动、复制或镜像，门窗/通路/反打关系正确。
- 检查交付卡内没有多余文字：资料卡只有两处标题，表情卡只有页眉与格标签，场景卡零文字。
- 检查交付目录内不存在过程图；修复用的单格重出件只留在 `reports/retries`。

## 调度与卡片边界

六格板可描述单镜或已核验的多镜头 GEN；空间连续性在每个电影 SHOT 内锁定，切点间按剪辑合同验证。整页优先生成，允许失败区域内部修复后合回。最终卡数量和版式保持，内部裁切不增加交付图。神话类型的肖像背景服从 production-type-and-mythic-film.md，不能用普通灰底默认覆盖已选风格。

## 表演资产贯通

角色表情卡、剧情首帧与六格故事板按 [actor-performance-workflow.md](actor-performance-workflow.md) 的PERF-ID映射。表情卡锁剧情状态及身份，不冻结全镜表情；首帧对应入态，故事板用原有六格呈现可见的接收与回应。静态验收检查状态差异和景别可读性，不能替代动态演技QA。
