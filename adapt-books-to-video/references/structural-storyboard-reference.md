# 白描分镜作为结构参考

适用于用户选择简笔画、白描或线稿来传达构图，且目标模型已核验支持分镜与主体图组合参考。模式记为 `STRUCTURE_ONLY`；这是资产职责约定，不是模型 API 参数。

## 能力依据与边界

2026-09-22 核验：[Seedance 2.5 官方提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)明确支持分镜与主体参考组合，推荐简约线稿，并用文字补充动作、摄影和风格；多宫格提供大致剧情参考，不严格对齐全部细节。原生首尾帧使用独立角色字段，不能与普通参考混同。

下列分工是据此制定的制作方法，不是平台保证。实际 Flova 路由及成片效果需单独验证；不能声称白描能彻底消除换脸，或存在未经文档证明的“只读几何”开关、参考权重。

## 资产分工

|资产角色|允许借用|排除项|
|---|---|---|
|`OPENING_LAYOUT` 单幅白描|开场位置、朝向、景别、机位、站坐高差和遮挡|脸、年龄、发型、服饰纹样、材质、色彩、笔触|
|`STORYBOARD_STRUCTURE` 多格白描|镜头顺序、视线、轴线、动作节点、构图关系|人物外貌、白底、格框、文字、线稿风格|
|人物资料卡|身份、脸型、年龄、发型、身形、衣着|卡片排版及文字|
|表情卡及 PERF 文字|当前镜头所需接收、回应和表演范围|强制全片一个表情、表情卡的宫格|
|已核对场景资产及文字空间锁|建筑拓扑、地标、材质、世界光向|其他机位的屏幕位置、九格版式|

按字段分配权威来源，不能再用“首帧锚点一律最高优先级”覆盖身份卡。白描布局与锁定建筑冲突时，先修布局；不能期待模型自行折中。未通过的写实板不能通过改名、描边或去色自动取得合格身份。

## 制作与编译顺序

1. 从已批准导演台和场景空间锁建立白描；用简化人物体块保留站坐、身高、朝向和肩部遮挡，不精绘五官或服饰。留足能判断动线的门、柱、坐垫等地标。画面少字，人物代号与真实身份在提示词中绑定。
2. 分别审查几何、可通行动线、正反打轴线、角色映射和动作可读性。白描不承担身份肖像 QA；资料卡与最终视频仍承担身份 QA。表演仍贯通 PERF-ID，不能因为脸被简化就删掉接收与回应。
3. 单幅称“开场构图参考”，不用“严格首帧”。本模式可用它替代写实首帧交付角色，但不冒充逐像素成片锚点。需要严格写实首帧时另选写实锚点模式，不能把白描塞入该槽。
4. 建上传清单：真实路径、哈希、审核状态、`reference_scope`、允许/排除信息、角色映射、格序→镜头/时间映射。这些是本地元数据，不直接当 API 字段提交。缺图时只出 `DEFERRED` 草案，不能写虚构上传成功或图片编号。
5. 白描以普通图参考参与多图任务，不作为 first_frame/last_frame，也不声明逐格为硬关键帧。准确接口确有角色字段才设置。Flova 按其当前文档和上传回执编译素材引用（如 `<<<image_N>>>`），不要把火山原生字段或 `@图片N` 原样搬进 CLI 参数。没有专用分镜字段不等于不能用普通图片加文字绑定；仍要核验实际路由。
6. 在正文逐项绑定身份/环境/布局职责，再写完整镜头和声音。明确实际输出为真人写实电影画面，继承指定角色脸与衣着、真实建筑材质和光线；不要呈现纸面、线条、分格、标签，也不要从草图变身真人。排除说明是提示意图，不是控制保证。
7. 多格不等于同数量切镜；同机位的动作前后采样仍属一镜，必须显式映射。反打背景随真实机位变化，但柱、门窗、供台位置不重建或镜像。

## 可改写的提示词片段

“[布局图引用]仅提供开场人物位置、朝向、站坐高差与镜头构图；[分镜图引用]仅提供格序对应的镜头、视线和动作节点。图中简化人物甲对应[甲资料卡引用]，乙对应[乙资料卡引用]。最终甲乙的脸、发型、身形与服装分别遵循各自资料卡；建筑、材质和光线遵循[场景引用及文字空间锁]。输出完整真人写实电影画面。白描的笔触、白底、格线、文字不进入影片；全片没有草图展示或草图转真人过程。以下按实际镜头描述动作与表演：……”

括号为编译占位，实际提交前必须替换并逐项核对上传回执。对白、节奏、风格、PERF 和当前项目无字幕/配乐策略须继续写入，不能只提交此片段。

## 视频验证

首次使用记录 `MODEL_CAPABILITY_DOCUMENTED / PLATFORM_ROUTE_PENDING / VIDEO_QA_PENDING`，完成后分别更新。用户授权试片时可用低分辨率验证身份衣着、线稿风格渗入、站坐眼线、建筑稳定、镜头数与对白时序。失败先定位职责冲突或布局错误；若持续风格渗入，简化结构图或在用户目标内切换写实锚点，不反复无界重抽。
